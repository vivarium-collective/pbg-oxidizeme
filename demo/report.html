About this demo. Running now: iML1515 (the M-model substrate that OxidizeME extends) via modern Python 3 cobrapy — three operating conditions, real FBA flux distributions — plus 6 reactors of real Beulig 2025 measured trajectories loaded from the digitized CSVs. Not running: OxidizeME itself (Python 2.7 / qMINOS install obstacle — see "Real bridge — install obstacle" below). When that stack is installed, the wrapper's port surface stays identical; the outputs gain proteome_allocations and damaged_proteome_fraction.

Composite architecture

The OxidizeMEStep consumes external_concentrations (EcoCyc-keyed, mM), ros_concentrations + metal_concentrations (nmol/L), and an optional mu_fixed. It emits mu, external_exchange_fluxes, proteome_allocations, damaged_proteome_fraction, and solver_status. Ports conform to the cell-side interface contract used by v2ecoli's multiscale-bioprocess investigation — drop-in interchangeable with v2ecoli baseline under the same reactor composite.

What OxidizeME adds on top of iML1515 (the bridge target)

iML1515 is an M-model — pure flux balance over the metabolic network. OxidizeME (Yang et al. 2019 PNAS) replaces the metabolic-only constraint set with a metabolism + macromolecular expression (ME) model that also tracks:

  • Protein synthesis as explicit reactions — every enzyme has a translation reaction; expression flux ≈ enzyme abundance × dilution rate; the ME-LP must allocate enough proteome to carry the metabolic flux.
  • Ribosome allocation — translation flux is bounded by ribosome availability, which itself is a translation product.
  • ROS damage and repair reactions — H₂O₂ / O₂⁻ damage Fe-S clusters and metal-dependent enzymes; repair complexes (IscU, alt-metallation, etc.) compete for proteome. Damaged enzymes are diluted out of the active pool.
  • Maintenance-vs-resistance trade-off — Beulig 2025's headline finding: at high cell density, increased maintenance burden re-allocates proteome away from resistance functions toward maintenance, pushing cells into a persistence state. iML1515 can't see this; OxidizeME can.

Operationally, the wrapper's extra outputs only populate under the real bridge:

  • proteome_allocations: map[float] — fraction per pathway (Σ MW × v_translation / Σ MW × v_translation_all)
  • damaged_proteome_fraction: float — Σ MW × v_ComplexFormation_damage / Σ MW × v_translation

Both formulas come straight from Beulig 2025's Methods section (doi:10.1128/msystems.00323-25). See OxidizeMEStep._compute_proteome_allocations and _compute_damaged_proteome in pbg_oxidizeme/processes.py.

Real bridge — install obstacle

The upstream OxidizeME stack runs on Python 2.7 / cobrapy 0.5.11 and requires qMINOS — a 128-bit-precision NLP solver — obtained by contacting Prof. M. A. Saunders, Stanford University. SoPlex (80-bit, academic-free) is an alternative. Both are required because ME-models are inherently ill-scaled.

Install paths (in order of friction):

  1. Pull SBRG's Docker image: docker pull sbrg/cobrame — pre-installed full stack.
  2. Source build: clone SBRG/cobrame + SBRG/ecolime + SBRG/oxidizeme + SBRG/solvemepy into a Python 2.7 venv with cobrapy 0.5.11.
  3. Request qMINOS (or use SoPlex).

Once installed, supply a pickled StressME model:

step = OxidizeMEStep(config={"me_model_pickle_path": "/path/to/stress_me.pickle", "strict": True})
sol = step.update({"external_concentrations": {"GLC[p]": 22.2, "OXYGEN-MOLECULE[p]": 0.21}})
print(sol["mu"], sol["proteome_allocations"], sol["damaged_proteome_fraction"])
